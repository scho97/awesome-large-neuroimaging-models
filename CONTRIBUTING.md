# Contributing

Thank you for your interest in contributing.

This list follows the Awesome List curation philosophy: **high-quality, well-documented, and actively useful resources only**.

The repository is <ins>not</ins> intended to aggregate all existing models or datasets. Instead, it curates resources that represent clear milestones in the field, credible candidates for reference or benchmark models, or unique and influential contributions to large-scale neuroimaging modelling.

This project is released with a [Contributor Code of Conduct](https://github.com/scho97/awesome-large-neuroimaging-models/blob/main/CODE_OF_CONDUCT.md). By participating, you agree to abide by its terms.

---

## General Guidelines

- One resource per pull request (or a tighly related group, when jutified)
- Chronological order within each section
- Use concise, factual descriptions
- No marketing or promotional language
- No dead links
- No personal blogs unless widely cited or community-recognised

---

## Inclusion Criteria (Checklist)

A model should satisfy **most** of the following:

- [ ] Publicly available paper or preprint
- [ ] Public code repository
- [ ] Clear description of training data
- [ ] Supports multiple tasks or datasets
- [ ] Explicit license for code and (if applicable) weights

A dataset should include:

- [ ] Clear license or data use agreement
- [ ] Documented consent / ethics approval
- [ ] Stable access link

---

## Entry Format

```markdown
- **Model Name** – short description (modality, scale, purpose, etc.).\
  [Paper | Code | Weights] (*Journal/Conference Year*)

- **Dataset Name** – short description (modality, scale, purpose, etc.).\
  [Website | Paper | Licence]
```

All links must be stable and publicly accessible.

---

## What Will Not Be Accepted

* Closed-source or undisclosed models
* Task-specific models without claims or evidence of generalisation
* Datasets without clear licensing or consent
* Promotional repositories
* Low-quality or abandoned projects

---

## Review Process

Maintainers may request:
* clarification on model scale, training data, or evaluation
* additional information regarding ethics or consent
* adjustments to categorisation or placement

Please note that pull requests that do not meet the above standards may be closed without merging.
